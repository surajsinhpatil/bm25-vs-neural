# Domain-Specific Search: BM25 vs. Neural Retrieval on Technical Documents

Information Retrieval course project, **Group 10**, BITS Pilani —
Surajsinh Patil (2025H1030058P), Tejas Mahajan (2025H1030057P), Swayam Kumud (2025H1030063P), Saksham Singhal (2025H1030208P).

We compare our own **BM25** with two dense retrievers used without fine-tuning
(**E5-base-v2**, **SPECTER2**) and their **RRF hybrids** on a frozen corpus of arXiv
**cs.CR** abstracts, using 50 queries in five categories (exact identifier, homonym, negation,
time constraint, paraphrase) and our own blind, double-annotated graded judgments.

## Research questions
| | |
|---|---|
| RQ1 | Does a dense retriever without fine-tuning beat BM25 overall? |
| RQ2 | How does the comparison change with the query type? |
| RQ3 | Does a science-specific model (SPECTER2) beat a general one (E5)? |
| RQ4 | Does an RRF hybrid beat both of its components, and for which query types? |
| RQ5 | How sensitive is BM25 to k1, b, stemming and tokenisation? |

## Running it
The easiest path is **`notebooks/kaggle_pipeline.ipynb` on Kaggle** (GPU on, Internet on, add
the dataset *"arXiv Dataset" by Cornell University*). It installs everything, builds the corpus,
validates on SciFact, produces the five runs and the judging pages, and zips the outputs.

Locally (Python ≥ 3.9):
```bash
pip install -e .                                  # core: numpy, scipy, nltk, matplotlib, pandas
pip install adapters pytrec_eval-terrier          # dense models (+ torch) and metric check
pip install --no-deps pyserini pyjnius            # only for the Lucene comparison (needs Java 21)
python -m pytest -q tests
```

Every run writes a TREC run file plus `<run>.eff.json` (index time, index size, per-query latency,
peak memory). All random choices use fixed seeds.

## Judging pages
All text is written into the HTML when the page is generated; the script on the page only
handles one-at-a-time display, grades, saving in the browser and export. A viewer that does
not run scripts still shows every item (read-only, with a warning). `make_judging_pages.py`
refuses to write a page with an empty query/description/criteria/title/abstract, a time query
without a date, or a document missing from the corpus, and re-checks every written page
against the frozen pool (`check_report.json`). `merge_judgments.py` refuses exports that were
made from a different pool. Tests: `tests/test_judging_pages.py`, `tests/test_judging_browser.py`
(headless Chromium: grading, saving across reloads, export, import, no-script view).

The corpus is not committed (size). `make_judging_pages.py` rebuilds it from the Kaggle arXiv
snapshot if `data/corpus/cscr.jsonl` is missing and compares its SHA-256 with
`data/corpus/EXPECTED.json` (the corpus the runs were made on).

## Judging protocol (summary)
* Pool: top-10 of all five runs; documents in any run's top-5 are judged first (phase 1).
* Each query is judged by two annotators (25 queries ≈ 750 documents per person); pairs are
  balanced so weighted Cohen's κ is estimated across all annotator pairs.
* The page never shows the system or rank; dates are shown only for time-constraint queries.
* Grades: 0 not relevant · 1 on topic but does not answer / breaks a condition · 2 relevant · 3 highly relevant.
* κ (linear and quadratic) is reported before adjudication; the qrels are frozen with a checksum
  before any metric is computed. Runs added later (stretch goals) get an extra blind round for
  their new documents (`make_pool.py --already-judged`).

## Validation status
* BM25 vs Lucene (Pyserini) on an offline 10,788-document collection: ΔnDCG@10 = −0.0026,
  96.8 % top-10 overlap, score ratio 1.900 = (k1+1) as expected (`results/offline_checks/`).
  The SciFact check (criterion i) runs in the notebook.
* Metric code equals `pytrec_eval` on every query (unit test with heavy score ties).
* Weighted κ equals scikit-learn's `cohen_kappa_score`.
